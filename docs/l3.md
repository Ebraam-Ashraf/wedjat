# Wedjat Layer 3: OS Kernel & Driver Subsystem Tracing

Layer 3 operates inside the Linux kernel on the host CPU. It hooks directly into the NVIDIA GPU kernel modules (`nvidia.ko`, `nvidia-uvm.ko`), the Linux virtual memory manager, network IRQ handlers, and the OS thread scheduler.

Where **Layer 1** gives host process/container identity and **Layer 2** captures application *intent* at the `libcuda.so` boundary, **Layer 3 reveals what happens after a CUDA call leaves user space** — why a kernel launch or memory op actually stalled once it hit the OS or the driver: page thrashing, CPU context switching, disk I/O locks, or network interrupt contention. This is the layer that explains cases where a user-space profiler reports "100% GPU utilization" but the job is still running slower than expected — the bottleneck is on the host side, not the silicon.

When a CUDA application calls something like `cuLaunchKernel` or touches unmapped Unified Memory, execution crosses from user space into kernel space via `ioctl` or a hardware page fault. Layer 3 uses eBPF `kprobes`, `tracepoints` (`tp_btf`), and — for active control rather than pure observation — `struct_ops`, to intercept those driver paths and observe host resource contention.

## 1. Core Hook Targets

The first design pass on Layer 3 settled on four hook points:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ LAYER 3: OS KERNEL & DRIVER SUBSYSTEMS (Host CPU Kernel Space)             │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
       ┌──────────────────┬────────────┴──────────┬──────────────────┐
       ▼                  ▼                       ▼                  ▼
1. nvidia-uvm.ko    2. nvidia.ko           3. sched_switch     4. softirq_entry
 (Unified Virtual   (Core Driver           (Linux CPU          (Network & Disk
  Memory Faults)     IOCTL Calls)           Scheduler)          Interrupts)
```

That set was later expanded to five subsystems, adding VFS/storage lock contention and an active-control path via BPF `struct_ops`:

```text
WHAT LAYER 3 EXTRACTS FROM THE OS & DRIVER:

1. Unified Virtual Memory (UVM) ──► nvidia-uvm.ko Page Faults
   • Faulting Virtual Address Range (VA) & Access Density
   • Host DRAM ↔ GPU VRAM Migration Latency
   • Page Eviction & Thrashing Events across oversubscribed workloads

2. Host CPU Scheduler Contention──► tp_btf/sched_switch
   • Context Switches per 1,000 launches (detects Noisy Neighbors)
   • Off-CPU Duration on CUDA Launch Paths (CPU starvation)
   • Thread Migration across NUMA sockets

3. Network IRQ & SoftIRQ Stalls ──► tp_btf/softirq_entry (NET_RX)
   • NIC Interrupt Contention sharing CPU cores with CUDA workers
   • SoftIRQ Handler Execution Duration (`do_softirq` -> `napi_gro_receive`)

4. VFS & Storage I/O Locks     ──► kprobe/do_sys_openat2 / dentry locks
   • Data loader I/O saturation on training dataset ingestion
   • Spinlock contention on VFS path resolution (`queued_spin_lock_slowpath`)

5. Active Driver Policies       ──► BPF struct_ops (gpu_ext)
   • Overrides driver page eviction algorithms (LRU/FIFO)
   • Enforces Time-Slice Group (TSG) hardware preemption for low latency
```

### Target 1 — Unified Virtual Memory (`nvidia-uvm.ko`)

Hooks the internal UVM page-fault handlers and memory-eviction functions, extracting the faulting virtual-address range, the faulting `pid`, resident-vs-evicted page counts, and page-prefetch efficiency. When VRAM is oversubscribed — e.g. a 30B-parameter LLM running alongside a training job — the default driver continuously migrates pages back and forth over PCIe. This target quantifies that migration rate and flags **Unified Memory thrashing** as the memory-bound bottleneck it is.

### Target 2 — Core GPU Driver (`nvidia.ko` / `nvidia_ioctl`)

Hooks entry and exit of `nvidia_ioctl` and `nvidia_mmap`, capturing `ioctl` command numbers, invocation frequency, memory-mapping operations, and channel allocations. Because it's a catch-all on the dispatch point, this tracking stays version-independent across driver releases rather than depending on internal symbols that might move.

### Target 3 — Linux CPU Scheduler (`tp_btf/sched_switch`)

Fires whenever a thread goes off-CPU, capturing off-CPU wait duration, the target `pid`/`tid`, and the next task scheduled. In multi-tenant environments a noisy-neighbor process (`stress-ng`, a background pod) can force the scheduler to time-slice a CUDA launch thread; this target measures context switches per launch burst and flags when host CPU preemption is starving the GPU before work ever reaches it.

### Target 4 — Interrupts & SoftIRQs (`tp_btf/softirq_entry` / `softirq_exit`)

Traces network (`NET_RX_SOFTIRQ`) and disk (`BLOCK_SOFTIRQ`) softirq handlers — interrupt vector ID, execution duration in µs, and CPU core. In distributed training, incoming network packet processing (collective communication, RDMA traffic) bound to the same core as a CUDA submission thread can delay collective launches by hundreds of microseconds, showing up as multi-rank stragglers.

### Target 5 — VFS & Storage I/O Locks (`do_sys_openat2` and friends)

Hooks kernel file-open and VFS lookup routines to catch data-loader bottlenecks — for example a PyTorch `DataLoader` triggering dentry spinlock contention (`queued_spin_lock_slowpath`) during dataset ingestion. This surfaces the exact kernel stack responsible when I/O, not compute, is the real limiter.

### Target 6 — Active Driver Policy Control (`gpu_ext` / BPF `struct_ops`)

The one non-passive target: instead of just observing, it uses BPF `struct_ops` inside the open-source kernel modules to override hardcoded driver routines — dynamically changing page-eviction schemes or forcing Time-Slice Group (TSG) hardware preemption to prioritize latency-critical inference workloads over background batch jobs.

## 3. Why It Matters: A Noisy-Neighbor Diagnosis Example

User-space profilers alone often can't explain a job that shows 100% GPU utilization but still runs slower than it should. Layer 3 isolates host-side root causes by correlating Layer 2's launch intent with Layer 3's scheduler and softirq events — a form of cross-layer differential diagnosis:

```text
SCENARIO: CUDA Kernel Submission Delayed by CPU Noisy Neighbor

  CUDA Launch Thread (PID 9107)           Linux CFS Scheduler / Kernel IRQ
─────────────────────────────────         ─────────────────────────────────
1. Calls cuLaunchKernel()
   │
   ▼ (Enters Kernel)
2. Trapped by sched_switch ────────────►  Preempted! (Swapped out for stress-ng)
   │                                      [ Off-CPU Duration: 650 µs ]
   │
3. Resumes Execution
   │
4. Trapped by softirq_entry ───────────►  Interrupted by NET_RX_SOFTIRQ!
   │                                      [ Network SoftIRQ Handling: 200 µs ]
   │
5. Finally Submits Work to GPU ────────►  GPU receives command 850 µs LATE!
```

By correlating the two layers, `wedjatd` can attribute an 850 µs submission delay to host CPU contention rather than a slow GPU kernel — a distinction a GPU-side-only profiler can't make. (The 850 µs figure here is illustrative of the diagnostic pattern, not a measured benchmark.)

## 4. C Code: Three Drafts of the Probe File

These are three successive drafts of the Layer 3 probe file, kept as written. They diverge on struct layout and `api_id` numbering (`101–104` in the first, `201–202` in the second, full ring-buffer events in the third) — reconcile onto one shared `wedjat_common.h` schema before wiring any of them into the real daemon build.

### 4.1 `driver_kprobes.bpf.c` — full four-probe version

Covers `nvidia_ioctl`, `uvm_va_block_service_fault`, `sched_switch`, and `softirq_entry`, all aggregating into the same per-CPU hash map.

```c
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>
#include "wedjat_common.h"

char LICENSE[] SEC("license") = "Dual BSD/GPL";

// --- External Maps (Declared in wedjat_common.h / host_ctx.bpf.c) ---

// 1. Fast-Path Aggregation Map (Per-CPU Hash)
extern struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_HASH);
    __uint(max_entries, 10240);
    __type(key, struct cuda_agg_key);
    __type(value, struct cuda_agg_val);
} agg_map SEC(".maps");

// 2. Slow-Path Ring Buffer for Notable Events
extern struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 256 * 1024);
} events_ringbuf SEC(".maps");

// 3. Thread ID to Physical GPU Device ID Mapping
extern struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10240);
    __type(key, u32);
    __type(value, u32);
} tid_to_device SEC(".maps");

// Helper: Get physical GPU ID for calling thread
static __always_inline u32 get_current_device_id(u32 tid) {
    u32 *dev_ptr = bpf_map_lookup_elem(&tid_to_device, &tid);
    return dev_ptr ? *dev_ptr : 0;
}

// ============================================================================
// 1. DRIVER IOCTL INTERCEPTION: nvidia_ioctl (nvidia.ko)
// ============================================================================
// Catches raw system calls between host processes and core GPU kernel driver
SEC("kprobe/nvidia_ioctl")
int BPF_KPROBE(probe_nvidia_ioctl, struct file *file, u32 cmd, unsigned long arg)
{
    u64 pid_tgid = bpf_get_current_pid_tgid();
    u32 pid = pid_tgid >> 32;
    u32 tid = (u32)pid_tgid;

    u32 device_id = get_current_device_id(tid);

    // Fast-Path Aggregation (API ID 101 = Driver IOCTL)
    struct cuda_agg_key key = {
        .pid = pid,
        .cgroup_id = bpf_get_current_cgroup_id(),
        .api_id = 101,
        .device_id = device_id
    };

    struct cuda_agg_val *val = bpf_map_lookup_elem(&agg_map, &key);
    if (val) {
        val->call_count += 1;
    } else {
        struct cuda_agg_val zero_val = { .call_count = 1, .total_bytes = 0, .total_latency_ns = 0 };
        bpf_map_update_elem(&agg_map, &key, &zero_val, BPF_NOEXIST);
    }

    return 0;
}

// ============================================================================
// 2. UNIFIED MEMORY PAGE FAULT TRACING: uvm_va_block_service_fault (nvidia-uvm.ko)
// ============================================================================
// Tracks UVM page fault events when VRAM is oversubscribed over PCIe
SEC("kprobe/uvm_va_block_service_fault")
int BPF_KPROBE(probe_uvm_fault_entry)
{
    u64 pid_tgid = bpf_get_current_pid_tgid();
    u32 pid = pid_tgid >> 32;
    u32 tid = (u32)pid_tgid;

    u32 device_id = get_current_device_id(tid);

    // Fast-Path Aggregation (API ID 102 = UVM Page Fault)
    struct cuda_agg_key key = {
        .pid = pid,
        .cgroup_id = bpf_get_current_cgroup_id(),
        .api_id = 102,
        .device_id = device_id
    };

    struct cuda_agg_val *val = bpf_map_lookup_elem(&agg_map, &key);
    if (val) {
        val->call_count += 1;
    } else {
        struct cuda_agg_val zero_val = { .call_count = 1, .total_bytes = 0, .total_latency_ns = 0 };
        bpf_map_update_elem(&agg_map, &key, &zero_val, BPF_NOEXIST);
    }

    return 0;
}

// ============================================================================
// 3. CPU SCHEDULER NOISE: tp_btf/sched_switch
// ============================================================================
// Measures when a GPU launch thread is preempted or goes off-CPU
SEC("tp_btf/sched_switch")
int BPF_PROG(trace_sched_switch, bool preempt, struct task_struct *prev, struct task_struct *next)
{
    u32 prev_pid = prev->tgid;
    u32 prev_tid = prev->pid;

    // Filter: Only track preemption if the off-CPU thread is an active GPU thread
    u32 *dev_id_ptr = bpf_map_lookup_elem(&tid_to_device, &prev_tid);
    if (!dev_id_ptr)
        return 0;

    u32 device_id = *dev_id_ptr;

    // Fast-Path Aggregation (API ID 103 = CPU Scheduler Preemption)
    struct cuda_agg_key key = {
        .pid = prev_pid,
        .cgroup_id = bpf_get_current_cgroup_id(),
        .api_id = 103,
        .device_id = device_id
    };

    struct cuda_agg_val *val = bpf_map_lookup_elem(&agg_map, &key);
    if (val) {
        val->call_count += 1;
    } else {
        struct cuda_agg_val zero_val = { .call_count = 1, .total_bytes = 0, .total_latency_ns = 0 };
        bpf_map_update_elem(&agg_map, &key, &zero_val, BPF_NOEXIST);
    }

    return 0;
}

// ============================================================================
// 4. INTERRUPT & SOFTIRQ NOISE: tp_btf/softirq_entry
// ============================================================================
// Detects when network (NET_RX) or disk interrupts disrupt GPU launch paths
SEC("tp_btf/softirq_entry")
int BPF_PROG(trace_softirq_entry, unsigned int vec_nr)
{
    u64 pid_tgid = bpf_get_current_pid_tgid();
    u32 pid = pid_tgid >> 32;
    u32 tid = (u32)pid_tgid;

    // Filter: Only record softirq interrupts affecting active GPU launch threads
    u32 *dev_id_ptr = bpf_map_lookup_elem(&tid_to_device, &tid);
    if (!dev_id_ptr)
        return 0;

    u32 device_id = *dev_id_ptr;

    // Fast-Path Aggregation (API ID 104 = SoftIRQ Interrupt)
    struct cuda_agg_key key = {
        .pid = pid,
        .cgroup_id = bpf_get_current_cgroup_id(),
        .api_id = 104,
        .device_id = device_id
    };

    struct cuda_agg_val *val = bpf_map_lookup_elem(&agg_map, &key);
    if (val) {
        val->call_count += 1;
    } else {
        struct cuda_agg_val zero_val = { .call_count = 1, .total_bytes = 0, .total_latency_ns = 0 };
        bpf_map_update_elem(&agg_map, &key, &zero_val, BPF_NOEXIST);
    }

    return 0;
}
```

**Technical key points:**

1. `nvidia_ioctl` kprobe is a catch-all hook on core driver dispatch inside `nvidia.ko`.
2. `uvm_va_block_service_fault` kprobe detects VRAM oversubscription and PCIe page-thrashing events from `nvidia-uvm.ko`.
3. `sched_switch` and `softirq_entry` BTF tracepoints measure host CPU preemption and interrupt contention (`NET_RX_SOFTIRQ`, `BLOCK_SOFTIRQ`) that starve CPU launch threads before work reaches the GPU.
4. Preemption and softirq events are recorded **only** when they hit an active GPU submission thread — gated on a `tid_to_device` lookup so unrelated host noise doesn't pollute the map.

### 4.3 `bpf/host_kernel.bpf.c` — ring-buffer event version

The most complete draft: tracks off-CPU duration per PID via a hash map, emits a `cuda_event` to a dedicated ring buffer only when a preemption stall exceeds 500 µs, and stubs out the softirq-vector filter for `NET_RX_SOFTIRQ`.

```c
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>
#include "wedjat_common.h"

char LICENSE[] SEC("license") = "Dual BSD/GPL";

// BPF Map for Layer 3 OS Noise Events
struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 256 * 1024);
} os_noise_ringbuf SEC(".maps");

// BPF Hash Map to track off-CPU start time per PID
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10240);
    __type(key, u32);   // PID
    __type(value, u64); // Off-CPU timestamp
} offcpu_start_map SEC(".maps");

// 1. Trace OS CPU Preemption (sched_switch)
SEC("tp_btf/sched_switch")
int BPF_PROG(trace_sched_switch, bool preempt, struct task_struct *prev, struct task_struct *next) {
    u32 prev_pid = prev->tgid;
    u32 next_pid = next->tgid;
    u64 now = bpf_ktime_get_boot_ns();

    // Record when a monitored thread is switched OFF the CPU
    if (prev_pid != 0) {
        bpf_map_update_elem(&offcpu_start_map, &prev_pid, &now, BPF_ANY);
    }

    // Measure how long the thread was off-CPU when switched back ON
    u64 *start_ts = bpf_map_lookup_elem(&offcpu_start_map, &next_pid);
    if (start_ts) {
        u64 offcpu_dur_ns = now - *start_ts;
        bpf_map_delete_elem(&offcpu_start_map, &next_pid);

        // Emit event if CPU preemption stall exceeded 500 µs (500,000 ns)
        if (offcpu_dur_ns > 500000ULL) {
            struct cuda_event *e = bpf_ringbuf_reserve(&os_noise_ringbuf, sizeof(*e), 0);
            if (e) {
                e->timestamp_ns = now;
                e->pid          = next_pid;
                e->tid          = next->pid;
                e->cgroup_id    = bpf_get_current_cgroup_id(); // Layer 1
                e->event_type   = 5; // 5 = CPU_PREEMPTION_STALL
                e->latency_us   = offcpu_dur_ns / 1000;
                bpf_get_current_comm(&e->comm, sizeof(e->comm));
                bpf_ringbuf_submit(e, 0);
            }
        }
    }
    return 0;
}

// 2. Trace Network SoftIRQ Contention (softirq_entry)
SEC("tp_btf/softirq_entry")
int BPF_PROG(trace_softirq_entry, unsigned int vec_nr) {
```

## 5. File Naming Convention

To keep Layer 3 modular and cleanly separated from the Layer 1/2 user-space probes, place these kernel probes in a dedicated file:

- **`host_kernel.bpf.c`** (alternatively `driver_kprobes.bpf.c`)
  - Contains `kprobes` for `nvidia-uvm.ko` and `nvidia.ko`
  - Contains tracepoint handlers for `sched_switch` and `softirq_entry`
  - Includes `wedjat_common.h` to share the same `struct cuda_agg_key` / event-map definitions used by Layers 1–2

## 6. Graceful Fallback Strategy in `wedjatd`

Kernel driver symbols inside `nvidia.ko` and `nvidia-uvm.ko` can vary between NVIDIA driver releases (e.g. driver 535 vs. 580), so attach failures need to be handled without taking the daemon down:

- **At startup**, `wedjatd` attempts to attach the Layer 3 `kprobes`.
- **On success**, it runs in **Full Visibility Mode** (Layer 1 + 2 + 3 + 4).
- **On failure** (restricted permissions, or driver symbols that moved), it logs a warning to `/var/log/wedjat/events.jsonl` and falls back to **Standard Mode** (Layer 1 + 2 + 4).

This guarantees `wedjatd` never crashes or fails to boot just because the host's NVIDIA driver updated unexpectedly.

## 7. Layer Summary (All Five Layers)

| Layer | Domain | Primary Mechanism | Key Telemetry Captured |
| --- | --- | --- | --- |
| **Layer 1** | Host OS Context | Kernel BPF Helpers | PID, TID, Process Name, K8s CGroup ID, CPU Core, Boot TS |
| **Layer 2** | User CUDA API | `uprobes` on `libcuda.so` | `cuLaunchKernel` dims, VRAM alloc bytes, PCIe transfers, CPU stall µs |
| **Layer 3** | **OS Driver & Kernel** | **`kprobes` / `struct_ops` on `nvidia-uvm.ko` & tracepoints** | **UVM page faults, PCIe page eviction, CPU context switches, SoftIRQ noise** |
| **Layer 4** | Physical GPU | NVML C API Polling | Board Temp (°C), Power (W), Overall GPU Util %, Xid Faults |
| **Layer 5** | GPU Silicon | PTX JIT Offloading (`eGPU`) | Physical SM ID (`%smid`), Block ID (`%ctaid`), Warp Divergence |
