# Wedjat Layer 4: Physical Hardware Telemetry (NVML)

Layer 4 is **not an eBPF program**. It runs in **user space** on the host CPU, inside `wedjatd` itself, calling NVIDIA's official C library — the **NVIDIA Management Library** (`libnvidia-ml.so` / `<nvml.h>`). It's the same library `nvidia-smi` and NVIDIA DCGM are built on.

Where Layers 1–3 are event-driven eBPF probes intercepting CPU execution the instant it happens, Layer 4 is **time-driven**: it polls hardware sensors (temperature, power shunts, clock registers, VRAM occupancy) on a periodic 1-second ticker, and separately listens — asynchronously, blocking — for hardware fault events (Xid codes like Xid 31 page faults, Xid 43 GPU hangs, Xid 79 PCIe drops).

Your CUDA code itself has no way to answer "how hot is this board" — compute kernels process numbers, they don't read hardware registers. NVML is the bridge: it runs on the host CPU and talks over PCIe to the GPU's onboard firmware to read those sensors.

## 2. Telemetry Inventory

The macro-level physical metrics eBPF can't reach from CPU memory alone:

| Telemetry Category | Exact NVML Metrics / Structs | Value to `wedjat` CLI |
| :--- | :--- | :--- |
| **Whole-Device State** | Compute Util %, Memory Bandwidth %, VRAM Used/Free | Overall board saturation (e.g. 87% Util, 6.2 GB VRAM used) |
| **Power & Thermals** | Power Draw (W), Power Limit (W), Temp (°C), Fan % | Thermal throttling and energy-consumption spikes |
| **Clocks & Performance States** | SM Clock (MHz), Memory Clock (MHz), P-State (`P0`–`P12`) | Frequency throttling during heavy matrix-math bursts |
| **Per-Process Accounting** | `nvmlAccountingStats_t` (GPU Compute %, Memory %, Peak VRAM) | Feeds the live process table directly |
| **Hardware Faults (Xid Errors)** | `nvmlEventSetWait()` event stream | Catches GPU memory page faults (Xid 31), driver hangs (Xid 43), PCIe drops (Xid 79) |

## 3. Execution Pattern: Poller + Blocking Listener

Because NVML gives you two different shapes of data — **polled values** (clocks, power, temperature, all answered on demand) and **blocking event notifications** (Xid errors, which fire whenever they fire) — `wedjatd` splits Layer 4 across two concurrent background threads: one on a 1-second ticker, one parked in a blocking wait. Two drafts of this pattern were sketched; both are kept here since the second tightens the wording without changing the mechanics.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ wedjatd DAEMON (User-Space Go Process)                                                 │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│  GOROUTINE 1: The 1-Second Sensor Poller (Time-Driven Loop)                            │
│  ┌──────────────────────────────────────────────────────────────────────────────────┐  │
│  │ Every 1,000 ms, wedjatd calls standard NVML C functions:                         │  │
│  │                                                                                  │  │
│  │  1. nvmlDeviceGetTemperature()       ──► Returns GPU core temp (e.g., 64°C)     │  │
│  │  2. nvmlDeviceGetPowerUsage()        ──► Returns real-time power (e.g., 115 W)   │  │
│  │  3. nvmlDeviceGetMemoryInfo()       ──► Returns VRAM used vs free (e.g., 5.8 GB)│  │
│  │  4. nvmlDeviceGetUtilizationRates() ──► Returns aggregate GPU Compute %          │  │
│  │  5. nvmlAccountingStats_t            ──► Returns process-level VRAM & %          │  │
│  │                                                                                  │  │
│  │  ──► MERGES these board metrics with eBPF call counts from Layers 1–3            │  │
│  │  ──► WRITES a 1-second snapshot row into SQLite (wedjat.db)                      │  │
│  └──────────────────────────────────────────────────────────────────────────────────┘  │
│                                                                                        │
│  GOROUTINE 2: Xid Hardware Crash Listener (Event-Driven / Blocking)                    │
│  ┌──────────────────────────────────────────────────────────────────────────────────┐  │
│  │ Hardware crashes (Xid errors) cannot be polled—they happen instantly.             │  │
│  │                                                                                  │  │
│  │  1. nvmlEventSetCreate()                                                         │  │
│  │  2. nvmlDeviceRegisterEvents(nvmlEventXidCriticalError)                          │  │
│  │  3. nvmlEventSetWait(INFINITE)  <── [BLOCKS & WAITS IN BACKGROUND]               │  │
│  │                                                                                  │  │
│  │  ──► When a hardware fault occurs (e.g., VRAM corruption or PCIe drop):          │  │
│  │  ──► Wakes up instantly and writes {"event": "xid_error"} to events.jsonl        │  │
│  └──────────────────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ wedjatd DAEMON (User-Space Go Process)                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  GOROUTINE 1: Periodic Poller (1-Second Ticker Loop)                        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Every 1,000 ms:                                                       │  │
│  │  1. nvmlDeviceGetUtilizationRates() ──► Compute % & Memory %          │  │
│  │  2. nvmlDeviceGetMemoryInfo()       ──► Used vs Free VRAM              │  │
│  │  3. nvmlDeviceGetPowerUsage()        ──► Micro-Watts -> Watts           │  │
│  │  4. nvmlDeviceGetTemperature()       ──► Core Temp in °C                │  │
│  │  5. nvmlAccountingStats_t            ──► Per-Process Peak VRAM & %      │  │
│  │  6. Merge with eBPF Layer 1–3 Map Deltas                              │  │
│  │  7. Commit 1s snapshot row to SQLite WAL (wedjat.db)                  │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  GOROUTINE 2: Xid Hardware Error Listener (Asynchronous / Blocking)        │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ 1. nvmlEventSetCreate()                                               │  │
│  │ 2. nvmlDeviceRegisterEvents(nvmlEventXidCriticalError)                │  │
│  │ 3. Loop:                                                              │  │
│  │      eventData = nvmlEventSetWait(timeout = INFINITE)  <── [Blocks]    │  │
│  │      Emit {"event": "xid_error", "code": eventData.eventData}         │  │
│  │      Append directly to /var/log/wedjat/events.jsonl                  │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

**Why Xid errors need their own thread:** functions like `nvmlDeviceGetTemperature()` return immediately with the current sensor value. Xid faults can't be polled the same way — they only arrive through NVML's event-subscription API, and `nvmlEventSetWait()` blocks until one physically occurs. Isolating that call in its own thread means a hardware fault gets caught instantly without ever stalling the 1-second metrics loop.

> ⚠️ **API name check:** both diagrams above (and the C code below) call `nvmlDeviceRegisterEvents(device, nvmlEventXidCriticalError, event_set)`. The real NVML constant is **`nvmlEventTypeXidCriticalError`** — confirmed against NVIDIA's current API docs. `nvmlEventXidCriticalError` (missing `Type`) won't compile; fix this when the code goes in.

## 4. Comparing the Layers

By layer:

| Layer | What Is It? | Where Does It Run? | How Is It Collected? | What Does It Tell You? |
| --- | --- | --- | --- | --- |
| **Layer 1** | Host Process Context | Host Kernel (eBPF) | Triggered when CUDA calls happen | Which PID/user/container is using the GPU |
| **Layer 2** | CUDA Driver API | Host Userspace (`libcuda.so`) | eBPF `uprobes` on CUDA functions | Kernel launch geometry, VRAM `malloc` size, CPU sync stalls |
| **Layer 3** | Kernel Driver & OS | Host Kernel (`nvidia-uvm.ko`) | eBPF `kprobes` & Linux tracepoints | UVM page faults, PCIe page eviction, CPU context switches |
| **Layer 4** | **Physical Hardware** | **Host Userspace (`wedjatd`)** | **NVML C API Calls (`libnvidia-ml.so`)** | **Board temp (°C), power (W), overall GPU util %, Xid hardware faults** |

By mechanism (eBPF vs. NVML specifically):

| Feature | Layers 1–3 (eBPF Probes) | Layer 4 (NVML Hardware Polling) |
| :--- | :--- | :--- |
| **What is it?** | Sandboxed eBPF bytecode loaded into the Linux kernel | Standard C API calls (`libnvidia-ml.so`) in user-space code |
| **Where does it run?** | Inside the Linux kernel / user-space probe boundaries | Inside your `wedjatd` daemon process on the host CPU |
| **How is it triggered?** | Event-driven: fires the instant a CUDA call or driver action occurs | Time-driven: polls on a 1-second ticker, or waits on hardware event signals |
| **What does it capture?** | Software intent (`cuLaunchKernel` dims, VRAM alloc bytes, CPU stall time, UVM faults) | Macro hardware health (Watts, °C, overall GPU Compute %, VRAM MB, Xid fault codes) |

**The sports-car analogy:** CUDA code is the pistons turning the wheels — the actual work. eBPF (Layers 1–3) is sensors on the gas pedal and gearshift, catching every microsecond the driver acts. NVML (Layer 4) is the dashboard — speedometer, fuel gauge, engine temp — giving steady readings once a second.

## 7. C Code

Both files below are the pure-C/pthread draft of Layer 4 (see the note in §5 on reconciling this with the Go directory layout).

### 7.1 `daemon/nvml/poller.c` — the 1-second ticker

Runs in a background POSIX thread, querying whole-device metrics and enabling per-process accounting (`nvmlAccountingStats_t`).

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <pthread.h>
#include <nvml.h>

typedef struct {
    unsigned int device_id;
    unsigned int gpu_util;        // GPU compute %
    unsigned int mem_util;        // Memory bandwidth %
    unsigned long long vram_used; // VRAM used in bytes
    unsigned long long vram_total;// Total VRAM in bytes
    unsigned int power_watts;     // Power draw in Watts
    unsigned int temp_c;          // Core temperature in °C
    unsigned int clock_sm_mhz;    // SM clock speed in MHz
} gpu_hw_snapshot_t;

void* nvml_poller_thread(void* arg) {
    nvmlReturn_t result = nvmlInit();
    if (NVML_SUCCESS != result) {
        fprintf(stderr, "[wedjatd] Failed to initialize NVML: %s\n", nvmlErrorString(result));
        return NULL;
    }

    unsigned int device_count = 0;
    if (nvmlDeviceGetCount(&device_count) != NVML_SUCCESS || device_count == 0) {
        fprintf(stderr, "[wedjatd] No NVIDIA GPUs detected.\n");
        nvmlShutdown();
        return NULL;
    }

    // Enable process accounting on all GPUs for per-process VRAM/compute tracking
    for (unsigned int i = 0; i < device_count; i++) {
        nvmlDevice_t device;
        if (nvmlDeviceGetHandleByIndex(i, &device) == NVML_SUCCESS) {
            nvmlDeviceSetAccountingMode(device, NVML_FEATURE_ENABLED);
        }
    }

    while (1) {
        for (unsigned int i = 0; i < device_count; i++) {
            nvmlDevice_t device;
            if (nvmlDeviceGetHandleByIndex(i, &device) != NVML_SUCCESS)
                continue;

            gpu_hw_snapshot_t snap = {0};
            snap.device_id = i;

            // 1. Compute & Memory Utilization %
            nvmlUtilization_t util;
            if (nvmlDeviceGetUtilizationRates(device, &util) == NVML_SUCCESS) {
                snap.gpu_util = util.gpu;
                snap.mem_util = util.memory;
            }

            // 2. VRAM Occupancy
            nvmlMemory_t mem;
            if (nvmlDeviceGetMemoryInfo(device, &mem) == NVML_SUCCESS) {
                snap.vram_used = mem.used;
                snap.vram_total = mem.total;
            }

            // 3. Power Usage (mW -> W)
            unsigned int power_mw = 0;
            if (nvmlDeviceGetPowerUsage(device, &power_mw) == NVML_SUCCESS) {
                snap.power_watts = power_mw / 1000;
            }

            // 4. Core Temperature (°C)
            unsigned int temp = 0;
            if (nvmlDeviceGetTemperature(device, NVML_TEMPERATURE_GPU, &temp) == NVML_SUCCESS) {
                snap.temp_c = temp;
            }

            // 5. SM Clock Speed (MHz)
            unsigned int clock = 0;
            if (nvmlDeviceGetClockInfo(device, NVML_CLOCK_SM, &clock) == NVML_SUCCESS) {
                snap.clock_sm_mhz = clock;
            }

            // TODO: Merge snapshot with eBPF Layer 1-3 map deltas and write to SQLite/Socket
        }

        sleep(1); // 1-second ticker interval
    }

    nvmlShutdown();
    return NULL;
}
```

### 7.2 `daemon/nvml/xid.c` — the blocking Xid listener

Runs in its own background thread; `nvmlEventSetWait()` blocks until a hardware fault physically occurs, so it can never stall the 1-second poller above.

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <nvml.h>

void* nvml_xid_listener_thread(void* arg) {
    nvmlEventSet_t event_set;
    if (nvmlEventSetCreate(&event_set) != NVML_SUCCESS) {
        fprintf(stderr, "[wedjatd] Failed to create NVML event set.\n");
        return NULL;
    }

    unsigned int device_count = 0;
    if (nvmlDeviceGetCount(&device_count) != NVML_SUCCESS) {
        nvmlEventSetFree(event_set);
        return NULL;
    }

    for (unsigned int i = 0; i < device_count; i++) {
        nvmlDevice_t device;
        if (nvmlDeviceGetHandleByIndex(i, &device) == NVML_SUCCESS) {
            // Subscribe to critical Xid hardware fault events across all GPUs
            nvmlDeviceRegisterEvents(device, nvmlEventXidCriticalError, event_set);
        }
    }

    while (1) {
        nvmlEventData_t event_data;
        // Blocks indefinitely until an Xid hardware/driver error fires
        nvmlReturn_t res = nvmlEventSetWait(event_set, &event_data, NVML_VALUE_NOT_AVAILABLE);
        if (res == NVML_SUCCESS) {
            // eventData.eventData contains the specific Xid error code (e.g., Xid 31, 43, 79)
            printf("[Xid Error Alert] Device GPU-%u triggered Xid Code: %llu\n",
                   event_data.gpuInstanceId, event_data.eventData);

            // TODO: Format JSON event and append to /var/log/wedjat/events.jsonl
        }
    }

    nvmlEventSetFree(event_set);
    return NULL;
}
```

**Key points:**

1. Zero eBPF overhead — these are ordinary C calls into `libnvidia-ml.so`, no BPF bytecode or verifier involved.
2. Thread separation — the 1-second sensor ticker and the blocking Xid listener run in separate threads so the poller never stalls waiting on a fault that may never come.
3. `event_data.gpuInstanceId` is only meaningful when MIG is enabled; on a non-MIG box it'll read 0 — worth swapping for `event_data.device` (or resolving the UUID) when wiring this into real per-GPU attribution.
4. Data fusion — every second, `wedjatd` correlates these NVML physical stats with the BPF map counters (`call_count`, `total_bytes`, `latency_ns`) from Layers 1–3 into one unified timeline row.
